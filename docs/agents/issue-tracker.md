# Issue tracker

Use GitHub Issues for [straw-hat-gupta/homelab-harness](https://github.com/straw-hat-gupta/homelab-harness/issues), accessed with the `gh` CLI when issue work is requested. See [triage labels](triage-labels.md).

Create implementation issues only for the next accepted [Stage 1](../stage-1.md) increment. Include its user-visible outcome, exclusions, open decisions, safety requirements, automated evidence and manual owner acceptance gate. Do not treat old platform issues, archived specs or future intentions as authorization to implement them.

Read an issue and its comments before work. Link concrete findings/evidence when updating status. Closing an issue requires the stated evidence, not a green historical suite or the model's claim of completion. Do not automatically close/relabel old issues as part of a documentation reset; triage is a separate requested task.

PRs follow the [template](../../.github/pull_request_template.md) and AGENTS.md. The maintainer merges unless explicitly instructing otherwise.
