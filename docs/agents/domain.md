This is one project context, with [GLOSSARY.md](../../GLOSSARY.md), the [active spec index](../spec/README.md) and [active ADRs](../adr/0012-managed-agent-runtime-and-cli-first-stages.md). They exist now; do not generate a parallel glossary or restore old decisions from a template.

Use the glossary's distinct meanings for client, runtime, model, harness instance, session, memory and audit. Read the owner document for an area before proposing a change. Flag contradictions explicitly and reconcile them before implementation; safety/secrets can only become stricter.

[Archives](../archive/README.md) and the preserved implementation are non-binding evidence. Active docs label proposed/open choices and future possibilities. If an implementation introduces a new concept, add it to the owning contract and glossary in the same scoped change rather than inventing new layers speculatively.
